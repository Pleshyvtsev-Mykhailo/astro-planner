# AstroPlanner: система планування астрономічних спостережень

Серверна частина (REST API) системи, яка показує, які об'єкти нічного неба видно з заданого місця й дня, та веде особистий журнал спостережень користувачів.

Автор: Плешивцев Михайло В'ячеславочич, ІПЗ-32. Індивідуальний STEM-проєкт («Мультиплатформне програмування»).

## Що вміє
- **Каталог** із 20 об'єктів Мессьє: пошук, фільтр за типом і яскравістю, сортування, сторінки.
- **Місця спостереження**: список міст із широтою й довготою (Київ, Львів, Тромсе).
- **Видимість**: для місця й дати рахує години темряви, чи сходить об'єкт у цій точці, його найвищу точку та криву висоти за ніч (144 точки, крок 10 хвилин).
- **Реєстрація та вхід** (JWT), ролі User та Admin.
- **Журнал спостережень**: особистий запис «що, де й коли я бачив». Кожен бачить лише свої записи, адмін бачить усі.

## Вимоги
- .NET SDK 10 (dotnet --version має показати 10.x)
- Git

Працює на Windows і Linux (перевірка платформ: docs/platform-check.md).

## Швидкий старт
```
git clone https://github.com/Pleshyvtsev-Mykhailo/astro-planner.git
cd astro-planner/backend
dotnet run --project src/AstroPlanner.Api
```
При першому запуску сервер сам створює базу SQLite, застосовує міграції й заповнює її. Нічого налаштовувати не треба. У консолі буде рядок `Now listening on: http://localhost:XXXX`.

| Що | Адреса |
|---|---|
| Інтерактивна документація та спроби запитів | `http://localhost:XXXX/scalar/v1` |
| Перевірка стану (має показати 20 об'єктів і 3 місця) | `http://localhost:XXXX/api/health` |

Сторінка `/scalar/v1` доступна лише в режимі розробки (`dotnet run` вмикає його сам).

Тестовий адміністратор (лише для розробки): логін `admin`, пароль `Admin123!`.

## Ролі та доступ

| Дія | Без входу | User | Admin |
|---|---|---|---|
| Дивитись каталог, місця, видимість | так | так | так |
| Змінювати каталог об'єктів | 401 | 403 | так |
| Додавати місце | 401 | так | так |
| Змінювати й видаляти місця | 401 | 403 | так |
| Вести журнал (свої записи) | 401 | так | так |
| Бачити, змінювати чужі записи журналу | 401 | 403 | так |
| Список користувачів | 401 | 403 | так |

401 означає «не авторизований» (немає токена або він хибний), 403 «авторизований, але немає прав».

## API

Усі відповіді в JSON. Помилки мають єдиний формат (ProblemDetails) без технічних подробиць.

| Метод і шлях | Призначення | Доступ |
|---|---|---|
| `GET /api/health` | Стан сервера | всі |
| `GET /api/objects` | Каталог: `search`, `type`, `minMagnitude`, `maxMagnitude`, `sortBy` (name, magnitude, ra, dec), `descending`, `page`, `pageSize` (до 100) | всі |
| `GET /api/objects/{id}` | Один об'єкт | всі |
| `POST`, `PUT`, `DELETE /api/objects` | Зміна каталогу | Admin |
| `GET /api/locations` | Місця: `search`, `sortBy` (name, latitude, longitude), `descending`, `page`, `pageSize` | всі |
| `GET /api/locations/{id}` | Одне місце | всі |
| `POST /api/locations` | Додати місце | увійшов |
| `PUT`, `DELETE /api/locations/{id}` | Змінити, видалити | Admin |
| `GET /api/visibility` | Видимість: `latitude`, `longitude`, `date`, `minAltitude` (за замовчуванням 20), `objectId` | всі |
| `GET /api/visibility/{objectId}/curve` | Висота об'єкта протягом ночі (144 точки) | всі |
| `POST /api/auth/register` | Реєстрація (ім'я латиницею, пароль від 8 символів) | всі |
| `POST /api/auth/login` | Вхід, у відповіді `accessToken` | всі |
| `GET /api/auth/me` | Хто я | увійшов |
| `GET /api/users` | Список користувачів без паролів | Admin |
| `GET`, `POST /api/observations` | Журнал: список (з фільтрами `objectId`, `locationId`, `from`, `to`) і створення | увійшов |
| `GET`, `PUT`, `DELETE /api/observations/{id}` | Запис журналу | власник або Admin |

Коди відповідей: 200, 201 (створено), 204 (без тіла), 400 (хибні дані), 401, 403, 404, 409 (конфлікт: дубль або об'єкт використано в журналі).

### Як працювати з токеном
1. `POST /api/auth/login` з тілом `{ "username": "admin", "password": "Admin123!" }`.
2. З відповіді візьми `accessToken`.
3. До захищених запитів додавай заголовок `Authorization: Bearer ТОКЕН`.

Приклади запитів:
```
GET /api/objects?type=Galaxy&sortBy=magnitude
GET /api/visibility?latitude=50.45&longitude=30.52&date=2026-11-15
```

## Як працює розрахунок видимості
- Положення об'єкта рахується за його небесними координатами, зоряним часом і координатами місця (спрощені формули, точність близько градуса).
- «Ніч» це час, коли Сонце опустилось нижче −12°.
- Висота рахується кожні 10 хвилин у вікні від місцевого полудня до наступного.
- Для кожного об'єкта визначається, чи він взагалі сходить у цій точці (`RisesAndSets`, `AlwaysAbove`, `NeverRises`).
- Місяць не враховується.

## База даних
SQLite, файл `astro.db` створюється поруч із застосунком (шлях задається налаштуванням).

- Таблиці: `CelestialObjects`, `Locations`, `Users`, `ObservationLogs`.
- Зв'язки через зовнішні ключі. Видалення об'єкта чи місця, які є в журналі, заборонене (відповідь 409), записи журналу видаляються разом із користувачем.
- Індекси на полях пошуку (назва об'єкта, тип, користувач і дата запису), унікальність назви об'єкта й імені користувача.
- Схема у третій нормальній формі. Роль і тип об'єкта зберігаються текстом: свідома денормалізація заради простоти.
- Усі запити виконує EF Core із параметрами, власного SQL немає (захист від ін'єкцій). Кожен запис це одна транзакція (`SaveChanges`).
- Таблиці створюють міграції EF Core, початкові дані заливає `DbSeeder` при першому запуску.

## Безпека
- Паролі зберігаються як хеш (`PasswordHasher`), у відповідях API їх немає.
- Токен JWT підписаний секретом; секрет для розробки лежить у `appsettings.Development.json`, а в іншому середовищі обов'язкова змінна `Jwt__Secret` (без неї сервер не запуститься).
- Автор запису журналу береться з токена, а не з тіла запиту. Доступ до запису описує політика «власник або адмін».
- Дані перевіряються (діапазони координат, довжина тексту, формат імені, дати).
- Помилки сервера пишуться в лог повністю, а клієнтові повертається коротке повідомлення.
- CORS дозволяє лише адреси з налаштування `Cors:Origins`.

## Налаштування

| Параметр | Де | Призначення |
|---|---|---|
| `Jwt__Secret` | змінна середовища | Секрет підпису токенів, мінімум 32 символи |
| `Jwt__Issuer`, `Jwt__Audience`, `Jwt__ExpiresMinutes` | змінна або `appsettings.json` | Видавець, аудиторія й термін дії токена (за замовчуванням 60 хв) |
| `Seed__AdminPassword` | змінна середовища | Пароль початкового адміністратора (без нього адмін не створюється) |
| `ConnectionStrings__Default` | змінна середовища | Шлях до бази, за замовчуванням `Data Source=astro.db` |
| `Cors:Origins` | `appsettings.json` | Адреси фронтенду, яким дозволено звертатись до API |

Приклад задання змінної: PowerShell `$env:Jwt__Secret = "довгий-секрет-від-32-символів"`, Linux `export Jwt__Secret=довгий-секрет-від-32-символів`.

Якщо запускати не через `dotnet run`, а зібраний застосунок, задайте `ASPNETCORE_ENVIRONMENT=Development` або змінну `Jwt__Secret`.

## Відомі проблеми
- **NU1202 при додаванні пакета.** `dotnet add package` без версії може взяти версію для .NET 11. Вказуйте версію 10.0.0 для пакетів EF Core, JwtBearer та Mvc.Testing.
- **Windows блокує запуск** («An Application Control policy has blocked this file»). Це Smart App Control. Запускайте проєкт у WSL (Linux) або вимкніть його.
- **Сервер не стартує поза `dotnet run`**: потрібен `Jwt__Secret` або `ASPNETCORE_ENVIRONMENT=Development`.
- **Порт.** Адресу береться з консолі (`Now listening on`), вона може відрізнятись від прикладів.

## Обмеження
- Формули спрощені (точність близько градуса), координати об'єктів наближені (епоха J2000), крок розрахунку 10 хвилин.
- Місяць і погода не враховуються.
- Імена користувачів лише латиницею, цифри та символи `_ . -`.
- CI не налаштовано: тести запускаються вручну.
