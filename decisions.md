# Журнал рішень

| № | Проблема | Рішення |
|---|---|---|
| 1 | Потрібна база даних без встановлення окремого сервера | SQLite: база лежить одним файлом, створюється сама при запуску |
| 2 | dotnet add package без версії підтягнув EF Core 11.0.0, несумісний із net10.0 (NU1202) | Версії пакетів EF Core зафіксовано на 10.0.0 |
| 3 | Попередження NU1903 для Microsoft.OpenApi 2.0.0 | Піднято до 2.7.5: ми лише генеруємо документ, а не читаємо чужі |
| 4 | Попередження про System.Security.Cryptography.Pkcs 9.0.0 | Піднято до 10.0.13 |
| 5 | Попередження про SQLitePCLRaw.lib.e_sqlite3, виправленої версії пакета немає | Приглушено через NuGetAuditSuppress. Ризик низький: SQL формує лише EF Core з параметрами |
| 6 | Windows блокує AstroPlanner.Api.exe (Application Control) | UseAppHost=false: запуск через dotnet.exe |
| 7 | Початкові дані мають з'являтись автоматично | Клас DbSeeder заливає каталог і місця при старті |

| 10 | Клієнту не можна показувати технічні подробиці помилок | Єдиний формат відповіді про помилку (ProblemDetails) без внутрішніх деталей |
| 11 | Сортування за довільним полем небезпечне | Дозволені лише чотири значення sortBy (перевірка регулярним виразом), інакше 400 |
| 12 | Великі відповіді | Пагінація, pageSize не більше 100 |
| 13 | Повторення коду об'єкта й видалення того, що вже використано | 409 для дубля й для видалення об'єкта чи місця, які є в журналі |
| 14 | Шаблон .NET 10 не має інтерфейсу для спроб запитів | Підключено Scalar (лише в режимі розробки) |
| 15 | SQLite у пошуку LIKE не помічає регістр кирилиці | Шукаємо ще й за кодом каталогу (M31), де регістр не важливий |
| 16 | Що вважати ніччю | Сонце нижче −12°, бо влітку в Києві воно не опускається нижче −18° |
| 17 | Пошук точного моменту сходу складний | Висота рахується кожні 10 хвилин |
| 18 | Розрахунки важко тестувати разом із базою | Формули винесено в статичні класи без залежностей |
| 19 | Місяць сильно ускладнює задачу | Не враховується|
| 20 | Паролі не можна зберігати відкритим текстом | Хеш PasswordHasher, у відповідях API його немає |
| 21 | Секрет JWT не має потрапляти в бойовий код | Для розробки секрет у appsettings.Development.json, поза розробкою обов'язкова змінна Jwt__Secret; без неї сервер не стартує |
| 22 | Різниця "не авторизований" і "немає прав" | 401, коли пропуска немає або він хибний; 403, коли роль не підходить |
| 23 | Читання каталогу має бути відкритим, а зміни захищеними | GET для всіх, зміни об'єктів лише для Admin, додавати місце може будь-який користувач |
| 24 | Назви даних у токені підмінялись довгими стандартними | MapInboundClaims = false, щоб лишились sub, name, role |
| 25 | Імена Admin і admin вважались різними | Перевірка унікальності імені без урахування регістру |
| 26 | Адмін потрібен при першому запуску | Створюється з пароля в налаштуваннях (Seed:AdminPassword), а не з жорстко вписаного значення |
| 27 | Чужий запис не повинен бути доступний | Політика "власник або адмін" окремим класом, який легко тестувати |
| 28 | Клієнту не можна довіряти критичні поля | Автор запису береться з токена, а userId у тілі запиту ігнорується |
| 29 | Чужий запис чи неіснуючий запис | 403 для чужого, 404 для неіснуючого |
| 30 | Журнал можуть засмітити хибними датами | Дата від 1900 року до завтрашнього дня |
